Smart AI-Powered Digital Tourism Platform (Jharkhand)

Monorepo with Vite React frontend and Express backend.

Quick start

Prerequisites
- Node.js (recommended: Node 22.12.0 or Node 20.19.0 LTS or newer)
- npm (bundled with Node)

1) Backend
   - cd backend
   - copy `.env.example` to `.env` and set secrets (create the file if missing)
   - npm install
   - npm run dev

2) Frontend
   - Ensure Node is upgraded to >= 20.19.0 or >= 22.12.0 (see notes below)
   - cd frontend
   - npm install
   - npm run dev

Health check
- Backend: http://localhost:5000/api/health

Notes on Node version
- Vite requires Node >= 20.19.0 or >= 22.12.0. If you have Node 22.11.x you will see an error telling you to upgrade.

Recommended Node installation methods (pick one)

1) nvm-windows (recommended)
- Install from: https://github.com/coreybutler/nvm-windows/releases (run installer)
- Example commands after installing nvm:

```powershell
nvm install 22.12.0
nvm use 22.12.0
node -v
```

2) Official Node installer
- Download Node 22.12.0 (or Node 20.x LTS >= 20.19.0) from https://nodejs.org/ and run the installer.

Troubleshooting
- If Vite fails due to Node version, upgrade Node.
- If ports conflict, stop the process using the port or use a different port. Set backend `PORT` env or run Vite with `--port`.
- If frontend reports socket/proxy connection refused, make sure backend is running and reachable at http://localhost:5000.

Deployment

Recommended target: Railway
- Railway is the best fit for this project because it runs the Express API, Socket.IO server, and React static build as one long-running Node service.
- The included `railway.json` uses the root `npm run build` command to install backend/frontend dependencies and build the frontend, then starts the Express server with `npm start`.
- The backend serves `frontend/dist` in production-style deployments, while API routes remain under `/api`.

Railway steps
1. Push this repository to GitHub.
2. In Railway, choose New Project → Deploy from GitHub repo.
3. Select this repo and keep the root directory as `/`.
4. Add environment variables as needed:
   - `JWT_SECRET`: required for secure auth tokens.
   - `ADMIN_SECRET`: required only if you need protected admin registration.
   - `OPENAI_API_KEY`: optional; without it, the chatbot uses built-in fallback answers.
   - `PORT`: optional; Railway normally provides this automatically.
5. Deploy. After deployment, verify `/api/health` on the Railway URL.

Vercel note
- Vercel is excellent for the React frontend, but this app also uses an Express API, Socket.IO, local JSON files, and SQLite fallback storage. Those features are better suited to Railway or another long-running Node host. If using Vercel, deploy only `frontend/` there and deploy `backend/` separately on Railway, then configure the frontend API base/proxy for the backend URL.

Persistence note
- The app can run with bundled JSON data and SQLite/local JSON user storage. For production data that must survive redeploys, attach persistent storage on Railway or migrate users/reviews/orders to a managed database.
